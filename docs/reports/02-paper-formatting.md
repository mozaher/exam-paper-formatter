# Report — Module 2: Essay / exam-paper formatting

## What was built

- **Papers**: assemble an exam from bank questions into ordered sections
  (Section A, B, …), each with optional instructions. Reorder sections and
  questions; override a question's marks for one paper without touching the
  bank; totals compute automatically.
- **Templates as named slots** (hard constraint): institution name, subtitle,
  footer text, default candidate instructions, font (serif/sans), paper size
  (A4/Letter). Pure data — no LaTeX/Word uploads, nothing executable.
- **Two print-ready PDFs per paper**:
  - the **question paper** — institutional header, instructions box,
    continuously numbered questions, lettered MCQ options, marks right-aligned
    per question, ruled answer space after essays (toggleable), footers with
    page numbers;
  - the **marking scheme** — same layout plus correct answers ticked and
    bolded, an answer key line per MCQ, each essay's marking guide in a shaded
    box, and a prominent "NOT FOR DISTRIBUTION TO CANDIDATES" notice.
- Demo data now includes a ready-made "Sample Midterm Examination" so both
  PDFs can be downloaded within a minute of setup.

## How you can verify it

```bash
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo --reset
python manage.py runserver
```

Sign in at http://127.0.0.1:8000/ as `teacher@demo.test` / `demopass123`,
open **Paper formatting → Sample Midterm Examination**, and click
**Question paper PDF** and **Marking scheme PDF**. Build your own paper with
**+ New paper**, then **+ Add questions** inside a section.

Tests: `python -m pytest -q` → **35 passing**. New ones to note:

- `formatting/tests/test_pdf.py` — the candidate PDF **never** contains model
  answers or the answer key; the marking scheme does; hostile markup in
  question text is escaped, not interpreted.
- `formatting/tests/test_papers.py` — marks overrides and totals; a question
  can't be placed twice on one paper; org A cannot open, download, or modify
  org B's papers, and cannot pull org B's questions into its own paper.

## The hard-constraint call (flagged, as agreed)

**No LaTeX exists in this module.** PDFs are generated by ReportLab, a pure-
Python library running in-process: no subprocess, no shell, no external
compiler, no network. The sandboxed-LaTeX constraint is about containing the
risk of compiling user-influenced markup server-side — this module removes
that risk class entirely rather than fencing it. Templates stay exactly as
specified: a fixed set of named slots. LaTeX will first enter the system with
the Paper MCQ module, because AMC requires it — and there it will run inside
AMC's separate, sandboxed container, satisfying both the licensing boundary
and the sandbox constraint in one place.

Trade-off accepted: no LaTeX-quality math typesetting in formatted papers for
now. If that becomes a requirement, it will ride the same sandboxed LaTeX
service Paper MCQ already needs — this module won't be weakened to get it.

## Other forks resolved

1. **ReportLab over WeasyPrint (HTML→PDF).** WeasyPrint needs system C
   libraries (Pango/Cairo) that routinely break `pip install` for
   non-developers and complicate deployment images. ReportLab is a wheel that
   installs anywhere. *Affects: cost/timeline and your ability to verify.*
2. **No logo/image upload in templates yet.** Image uploads add a media-storage
   and file-validation surface (and uploaded files vanish on ephemeral hosts
   without object storage). Text-only branding ships now; a logo slot with
   proper image validation and storage is a clean later addition. *Affects:
   security and deployment cost.*
3. **Marking scheme as a first-class output.** Cheap to build alongside the
   question paper and immediately valuable; the candidate/staff separation is
   enforced by tests on the rendered bytes because leaking a marking guide
   into a printed exam is this module's worst failure mode.
